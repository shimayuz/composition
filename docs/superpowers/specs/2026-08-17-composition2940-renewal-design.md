## 1. 目的と背景

現サイト（医療AIコンサルティング紹介サイト）を、**AI駆動開発・AI研修事業**のコンバージョンサイトへ全面リニューアルする。デザインは「売れるデザイン＝Whyに対してBecauseのあるデザイン」を要件とし、売上実績のある海外7社・日本8社のサイト構造リサーチ（別紙: composition2940-renewal-research.md）から抽出した定石に準拠する。

### 適用する定石（リサーチ結論）
1. FVは機能でなく「変化の約束」
2. Becauseは「証拠→数字→人物」の順で積む
3. 動くプロダクトを見せるのがコピーより先
4. CTAは「ソフト×ハード」複線を全セクション末に反復＋不安打消し文
5. 研修LPは助成金独立セクション＋入口分岐
6. Newsの時系列で「動的権威」を演出
7. トーンは単価と整合させ「売り込み感」を消す

## 2. ポジショニングとブランドコンセプト

- **ポジショニング**: 汎用AI駆動開発・AI研修事業 × 「実装する医師CEO」ブランド
- **コンセプト**: **「医療で鍛えたAI実装力を、すべての現場へ」** — 最も規制が厳しく失敗が許されない医療現場で自らAIを実装してきた事実を Because の起点に置き、全業種へ展開する
- **Heroコピー方向**: 実装者宣言型。候補（制作時に磨く）:
  - 「AIは、実装で語る。— 医療の現場から。」
  - 「作って、動かして、証明する。医師がやるAI開発。」
  - サブコピーで「現役医師×開発者が、AI駆動開発と研修で伴走します」を明示

### プロダクトカンパニーとして見せる（2026-08-18追加）
- **「コンサルティング」という語をサイト全体から排除**する。サービスは「AIプロダクト開発」「AI駆動開発」「AI研修」の実装ベースの表現に統一
- 副目的: **Google系スタートアップ支援プログラム（Google for Startups Cloud Program等）の採択**。受託・コンサル主体と見なされないよう、自社プロダクト（診療報酬加算ナビ等）と技術発信を前面に出し、「プロダクトを持つテック企業」として構成する
- 会社紹介・Aboutでも「戦略支援」「アドバイザリー」系の語彙を避け、「作る・動かす・教える」の動詞で語る

### スコープ制約（ユーザー指定）
- **リファラクは掲載しない**
- **株式会社quaiへの言及はしない**（合同会社コンポジション単体のサイトとして構築）
- 診療報酬加算ナビ（shinryohoushu.com）は**独立ドメインのまま**、プロダクト紹介＋相互リンクで紐づける（quai社名は出さない）。加算ナビへの流入導線をトップ・医療サービスページの両方で確保する

## 6. デザイントーン

- **配色**: クリニカルホワイト基調 × ディープネイビー × 医療ブルーのアクセント（清潔感・信頼感と「実装者の証明」の両立）。現行の緑（#3a5a40）は廃止
- **タイポグラフィ**: 太めのサンセリフ（Noto Sans JP系）。見出しは大きく、余白広め
- **ビジュアル**: 製品UIスクリーンショット主役＋人物（代表）写真。装飾イラストは最小限
- **トーン**: 売り込み感を消した「実績報道型」。誇張コピーより事実の提示

## 6b. Anti-AIデザイン規範（2026-08-18追加）

「AIが作ったサイト」に見える記号を徹底的に排除し、アクセスしたくなるクラフト感を出す。

### 禁止パターン（AI感の記号）
- **Lucide / Heroicons / Font Awesome 等の既製アイコンセットをそのまま使うこと**
- 紫〜青のグラデーション背景、グラスモーフィズムカード、意味のない抽象3Dイラスト
- 絵文字の見出し・箇条書き、「〜を実現します」の同型文の羅列
- ストックフォトのAI風人物・握手写真
- 均一な角丸カード3枚横並びだけで構成されたセクションの連続

### 採用パターン
- **アイコン**: 以下のいずれかで統一感のあるカスタムピクトグラムを用意
  1. 質の高いフリーvector素材（統一されたトーンのセットを1つ選定）
  2. 画像生成でピクトグラムを自作（ユーザーが生成 → ClaudeがPNG→SVGベクタ化・単色化・最適化）
- **写真**: 実在の人物（代表）・実際の現場・実際の製品UIのみ。診療報酬加算ナビの人物写真の使い方をトーンの参考にする
- **レイアウト**: エディトリアル（雑誌）的な非対称グリッド、大きな実写・実UI、本文の情報密度で信頼を作る
- **モーション**: 過剰なスクロールアニメーションは使わず、控えめなフェード程度

### 素材ワークフロー
- 画像素材は**ユーザーが準備**する（人物写真・画像生成ピクトグラム）。Claudeは必要素材のリスト（枚数・被写体・構図・トーン指定）を提示し、受領後にSVG変換・圧縮・組み込みを行う
- PNG→SVG変換はClaude側で実施（vtracer/potrace等）

## 7. CTA設計

- **ハードCTA**: 無料相談 — TimeRex埋め込み（/contact および各ページのCTAボタンから）
- **ソフトCTA**: 研修LPの資料DL。将来的に診断型フロントエンドを追加検討（Phase 2）
- **加算ナビ導線**: トップ・/services/medical・/products の3箇所から shinryohoushu.com へ外部リンク
- ボタン近傍に不安打消し文（例:「売り込みはしません」「30分・オンライン」）

## 8. 技術スタック

- **フレームワーク**: Next.js（App Router）+ TypeScript + Tailwind CSS（現行と同一系統、新規構築）
- **ホスティング**: Cloudflare（現行踏襲。デプロイ方式は実装時に確認）
- **News管理**: 当面はMDXファイルベース（CMSはPhase 2で検討）
- **既存資産**: 旧リポジトリ（~/CascadeProjects/CompositionWebsite）から画像等のみ流用
- **shinryohoushu.com側**: 相互リンク（運営・開発元としてcomposition2940.comへのリンク設置）は本スペックのスコープ外、別途対応
